### How the proposed format compares

- Pre-baked `.pmtiles` as an asset next to the upstream `enc` asset is the real differentiator. No prior art ships a derived, render-ready rendition alongside the source; OpenCPN pushes an S-57 → SENC build onto the client, and that build is the reason chart installation currently requires a developer toolchain. Keeping the upstream URL in the same item preserves provenance and leaves a path to converting on device.
- Real coverage MultiPolygons per item make coverage preview and "what covers me here" trivial. NOAA has this too, but only inside its own dialect; OsmAnd and the OpenCPN UI do not.
- `license` as an SPDX identifier plus `providers` at collection level lets the catalog be filtered on redistributability, which is what `ow:tier` encodes. Neither NOAA nor OpenCPN carries a licence field at all, so redistribution rights live in someone's head.
- Sizes and SHA-256 checksums on the tile asset are what make a free-space check, resume, and verify possible. Nobody else publishes checksums.
- Mirroring `enc:edition` and `enc:update` keeps OpenCPN's update detection, in a format a mobile client can parse without a second parser.

### Gaps to close

Measured against the current build (7,048 NOAA cells) and the published copy on `tiles.openwaters.io`.

- Gzip and `ETag` are live on the published documents: `items.json` costs 830 KB on the wire and an `If-None-Match` check against an unchanged copy returns `304`. That is a twelfth of what NOAA's own product catalog costs for the same information. A digest document the app polls first, or STAC's paged items, earns its keep only once a single collection outgrows that.
- One `.pmtiles` per cell means a regional download is thousands of files. OsmAnd hands out one file per region for a reason. A merged per-region or per-band tile asset alongside the per-cell ones is worth having, once a consumer defines what a region is.
- Nothing sits between collection and item. Coast Guard district, state and region exist only as `enc:tags` strings in a NOAA-specific vocabulary, and a browse UI wants them as facets. Two of the three namespaces are self-labeling; `region` is an opaque NOAA code (`region:40`) that needs a label map before it can be shown to anyone.
- Overlap between collections is unspecified. When NOAA and a future CHS or UKHO collection cover the same water, something has to decide display priority. This is not the `partition` asset's job: that file is tile57's per-collection ownership map and knows nothing about other collections. Preferring the larger compilation scale answers it without a new field, and the format doc should say so.
- Checksums prove integrity, not authenticity. A user-added catalog URL is a trust boundary: it can point the app at arbitrary downloads. HTTPS-only, a pinned default catalog, and a signature over `catalog.json` are the cheap mitigations.
- STAC conformance is one error away, not a fork. `catalog.json` and `collection.json` already validate against STAC 1.0.0 untouched; items fail on a single missing `links` property. Adding `root`, `parent` and `collection` links per feature costs 11 KB gzipped across all 7,048 of them, which buys real conformance for 1.4% of the payload.
- Product types beyond ENC — basemap, S-102 bathymetry, S-104/S-111 — need an asset role vocabulary before the second collection lands.
